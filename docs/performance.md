# 性能验证

本轮为 1.14.1 / versionCode 29 的未归档维护，保持现有切日、闪烁、提醒和数据语义。Room schema 仍为 5。

## 本机布局基准

2026-10-15，macOS 主机、Temurin 17.0.20.1、Debug Kotlin 字节码、JVM 最大堆 768 MiB。每档预热 5 次、采样 9 次，分别取耗时和当前线程分配字节的中位数。事件类型交错，`start=480+i`、`end=900+i`，冲突备注为空，单独测量 `TimelineLayoutPlan.build`。

| 日程数 | 切片数 | 优化前 ms | 优化后 ms | 优化前分配字节 | 优化后分配字节 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 10 | 19 | 0.283 | 0.181 | 94,624 | 21,760 |
| 50 | 99 | 2.662 | 1.214 | 2,236,832 | 156,256 |
| 100 | 199 | 11.210 | 1.025 | 19,350,848 | 471,808 |
| 200 | 399 | 76.734 | 2.253 | 113,985,384 | 2,035,664 |
| 300 | 599 | 261.127 | 3.327 | 377,826,488 | 4,886,048 |

修复前，每个切片的覆盖下标判断都会再次过滤整个事件组；现在每次构建只分组一次。分配量是 JVM 线程分配计数，包含临时对象，不是应用驻留内存。短样本受 JIT 和 GC 影响，结果用于同条件对照，不能直接换算 Android 帧率或真机启动速度。

先运行项目构建或 `:app:compileDebugKotlin`，再使用 JDK 17+ 复现：

```bash
python3 scripts/benchmark_timeline.py --java-home "$JAVA_HOME" \
  --output app/build/reports/performance/layout.json
```

脚本默认读取当前 Debug 编译目录与 Gradle 缓存的 Kotlin 2.3.10 标准库，也可用 `--classes`、`--kotlin-stdlib` 指定路径。原始本轮结果保存在本机构建目录的 `before.json` 和 `after.json`。

## 行为与资源验收

- 以发布前算法作为差分参照，覆盖稀疏、密集、传递重叠、首尾相接、重复 id、完成态、无效记录和 1–3 倍文字指标，比较提示、统计、切片及时间坐标。
- 连续访问 1000 个日期，宽限结束后只有活跃页和最多 12 个闲置日期的共享 Job；同日消费方共用状态，释放其中一个不影响其他消费方。
- 导入覆盖 1000 行、错误行、勾选恢复、慢旧输入晚返回、切换回退日期和 SQL 失败回滚；只有最新版本可提交。
- 20 个在途刷新请求合并为一次后续处理，保留最新数据和强制刷新标志；完成命令分别落库。提醒覆盖夏令时、午夜、回拨、禁用、精确闹钟回退与账本持久化失败重试。
- 小组件同一进行中区间不重新加载列表；事件边界更新摘要，午夜、数据与实例变化、系统强制更新刷新列表。
- Compose 回归覆盖 320/360/600dp、1/1.5/2 倍字体、深浅主题、动画曲线与组合次数，以及大重叠组最后一行可达。

冷启动修复仍在事务内迁移 `default` 并执行原合并规则。候选 SQL 只减少无重复历史记录的实体加载，仍有全表分组成本。完整冲突备注在全密集数据下自身可达平方规模。

验证采用 JVM、Robolectric、Debug Lint、Release Vital Lint 和签名 APK 检查。实际设备帧耗时、Doze、OEM 小组件宿主及 HyperIsland 表现需要单独设备验证。
